01

GitHub, by asking

Your work lives on GitHub, but you never type git commands. Codex does all of it. When you want your work saved and online, you say one word: "push".

Two things never to doDon't type git commands yourself, and don't upload or edit files on github.com. Both make two versions of your work that disagree. Ask Codex instead.

Once, on Day 1

  1. Make a GitHub account.

    At github.com, before Day 1 if you can. Use a username you'd be happy to see on an exhibition label.

  2. Start Codex in your Documents folder.

    Following Codex setup.

  3. Paste the setup prompt.

    Fill in the two brackets first. Codex checks what's installed, signs you in to GitHub through your browser, creates your project from the studio starter, and puts your press online. Approve each step it asks about.

    Setup prompt
    Set me up for Computationally Yours. My GitHub username is [username] and I'd like my project folder called [project-name].

1. Check that git and the GitHub CLI (gh) are installed. If not, tell me what you'll install and wait for my yes.
2. Check that I'm signed in to GitHub with gh. If not, start the browser sign-in and tell me exactly what to click or copy.
3. Create my public repository from the template kala0606/computationally-yours-starter and download it here.
4. Set my git name and email from my GitHub account (use the GitHub noreply email if mine is private).
5. Turn on GitHub Pages for the repository (main branch, root folder).
6. Give me the link to my repository and to my press (https://[username].github.io/[project-name]/), and tell me exactly what to type to restart Codex inside the project folder.

Don't ask me to type any git commands.
  4. Restart Codex inside your project.

    Codex tells you the one line to type. From then on it reads the project's AGENTS.md, which tells it to handle every git step for you.

What to say, every day

SayCodexWhen
"push"Saves everything with a message saying what changed, and puts it on GitHub. Tells you what it saved and gives the link.At least once a day, and whenever something works.
"checkpoint"Saves a point you can return to, without putting it online.Before you ask for a big change.
"go back"Shows what changed since the last save, and returns to it only when you say yes.When a change broke something.
"status"Tells you what's changed and whether everything is online.Whenever you're unsure.
"is it online?"Checks your repository on GitHub and says what a visitor sees.Before a critique or a deadline.

Codex shows you, in one short line, what it ran. You don't need to understand it, but read it before approving, as with any change.

If something goes wrong

  • Codex says the push was rejected. Say "fix it and push". It fetches what's on GitHub and merges it.
  • Codex says there's a conflict. Stop. Don't let it delete anything; call the facilitator over.
  • Codex says a file is too big. Let it add the file to .gitignore, and keep the file on the studio drive.
  • Signed out of GitHub. Say "sign me in to GitHub again".
02

Setup

Day 1. About thirty minutes. These are the only commands you'll ever type; from here on, everything else (including git) is something you ask Codex for. If a step fails, stop and ask; don't work around it.

  1. Open a terminal.

    Terminal on a Mac, or the terminal inside VS Code. If you've never used one, that's fine.

  2. Install Codex.

    This needs Node.js. If the command isn't found, ask before installing anything else.

    npm install -g @openai/codex
  3. Start Codex in your Documents folder.

    Type these two lines.

    cd ~/Documents codex
  4. Sign in with the studio account.

    Use the account the studio gives you, not a personal one. Never paste a password or key into a prompt.

  5. Paste the GitHub setup prompt.

    It's on the Repository page. Codex signs you in to GitHub, creates your project from the studio starter, and tells you the one line to type to restart inside it.

  6. Ask your first question, read-only.

    Now inside your project. This checks that Codex can see your files and that you can read what it says.

    Read this folder and tell me, in plain language, what is in it. Don't change anything.
  7. Say "push".

    Codex saves your work and puts it on GitHub, then gives you the link. Say it whenever something works, and at the end of every day. Say "checkpoint" before a big change, and "go back" if something breaks.

If you prefer working in an editor, Codex is also available as a VS Code extension, using the same account. Keep approvals on, so Codex asks before it edits files or runs commands, until you're confident reading its changes. Your project's AGENTS.md tells Codex about you, your identity, and how to handle git for you; section 09 covers it.

03

Ground rules

Codex is fast and fluent, which is exactly why authorship needs rules. These hold all month.

  1. You decide; Codex proposes. Every rule in the system has a reason in the identity's position. Codex doesn't get to supply the reasons.
  2. Plan before code. Ask for a plan first, agree it, then ask for one step at a time.
  3. Read every change before you accept it. If a change is too big to read, ask for a smaller one.
  4. If you can't explain it, you can't keep it. Ask Codex to explain the code, then explain it back in your own words in your log.
  5. The words are yours. Codex never writes your manifesto, your statement, or the Decided line in your log. It may question them.
  6. Record what you rejected. The authorship log keeps what Codex suggested, what you kept and what you turned down, with reasons.
  7. Check every fact. Codex can invent libraries, datasets and references that don't exist. Open them yourself.
  8. Nothing private goes in. No passwords, keys or other people's personal data in prompts or in the repo.
04

How to ask

A good prompt has five parts. Point at your files rather than retyping them: Codex can read identity.md, manifesto.md and your code.

Role

Which of the five roles it's playing.

Context

The files to read and what they are.

Task

One thing. Not three.

Limits

What it must not do or change.

Check

How you'll both know it worked.

Weak
make it look cooler and add more stuff

No role, no context, no limits. Codex will guess, and its guesses come from everyone else's work.

Strong
You're my collaborator. Read manifesto.md and src/draw.js.
Rule 2 says absence is drawn heavier than presence, but
line weight is currently fixed. Change only the line-weight
calculation so it follows the deficit column in data/rain.csv.
Don't touch the grid or the export. When you're done, render
seed 41822 and tell me the thinnest and thickest weights.

Names the role, the files, the rule it serves, the one change, what to leave alone, and a check.

08

Saving habits

Three habits cover the month. All of them are things you say to Codex.

  1. Say "checkpoint" before you ask for a big change.

    Then "go back" always has somewhere safe to return to.

  2. Say "push" when something works, and at the end of every day.

    Your laptop is not a backup, and pushing lets the facilitator see your work.

  3. Check the message Codex saved with.

    It should say what changed, like "line weight follows deficit", not "update". Ask it to reword it if not.

Large filesGitHub refuses single files over 100 MB. Keep raw scans, videos and large meshes on the studio drive. Codex will warn you before saving anything over 50 MB.

What to say

Like git, you work the press by asking Codex.

SayCodex
"preview"Starts the press on your laptop and gives you a link to open.
"make a dial for …"Adds a parameter to config/params.json with a sensible range, uses it in your rules, and asks you for the identity's reason.
"change rule 3 so …"Edits src/system.js, one rule at a time, and explains the change.
"render twenty"Writes twenty outputs, named by seed, into outputs/digital/.

12

Dials

Each dial in config/params.json becomes a control. You don't need to edit the file by hand, but it helps to read it.

One dial
{ "key": "rows", "label": "Rows", "type": "range",
  "min": 4, "max": 160, "step": 1, "value": 48,
  "reason": "One row for each year of the record." }
TypeControl
rangeA slider with a number box: min, max, step.
numberA number box.
toggleOn or off.
selectA choice from options.
colorA colour picker.
textA line of text.

The top of the file also sets the identity's name, the work's title and the paper (A2 is 420 × 594 mm, with a margin). The reason is the identity's reason, and it shows under every control, so write it as carefully as the manifesto.

17

When it goes wrong

  • It changed far more than you asked.Don't accept it. Say "go back" (prompt 03) and ask again with tighter limits.
  • It's going round in circles.Start a fresh session. Give it a three-line summary: what works, what doesn't, the one thing to fix.
  • It says it's done, but the output is wrong.Ask it to run the code and show you the result, then describe what you expected to see.
  • It used a library or source you can't find.Assume it doesn't exist until you've found it yourself.
  • You don't understand what it wrote.Stop and use prompt 02. Don't build on code you can't explain.
  • The outputs have started to look like everyone else's.Use prompt 15, then go back to the manifesto, not to Codex, for the next rule.

Going public
