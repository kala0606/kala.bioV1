    Creative Coding, lightly.

    Enough programming to make things move, wobble and surprise you. We go from "what is a variable" to "what is a class", and take a long, playable detour through Perlin noise and shaders on the way.

    This page is language agnostic in spirit and p5.js in practice. Every idea here (variables, loops, functions, objects) exists in Python, C, Java, Rust, whatever you meet next. We use p5.js because it is JavaScript that draws, it runs in a browser tab with zero setup, and it is the language of the best free programming teacher on the internet.

    The two functions you will write forever

    A p5 sketch is a program with two special functions. setup() runs once. draw() runs again and again, about 60 times a second, and each run paints one frame. Animation is just "draw something slightly different each frame".

    • Comment out background(...) with // and run again. Why does the circle leave a trail?
    • Change 60 to mouseX. Now the size is a variable too.
    • Break it on purpose: delete a bracket, press Run, read the console under the canvas. Errors are normal. Reading them is the skill.

    The canvas is a grid of numbers

    Before variables, one fact: the origin (0, 0) is the top left, x grows right, y grows down. Every drawing command is just numbers on this grid.

    chapter 1

    Variables & memory

    A variable is a labelled box in the computer's memory. That's it. Everything else is detail.

    Your computer's RAM is billions of tiny numbered slots. A program that says let x = 50 asks for a slot, writes 50 in it, and remembers that the slot is called x. Later, x = x + 3 reads the box, adds 3, and writes the result back into the same box. The label stays, the contents change. That is why they are called variables.

    Three kinds of things you'll put in boxes (for now)

    • Numbers: 3, -0.5, 400. In JavaScript every number is a 64-bit float (8 bytes). Other languages make you choose: int vs float.
    • Strings (text): "hello". Roughly 2 bytes per character.
    • Booleans: true or false. One bit of information, though it usually gets a whole byte because memory is handed out in bytes.

    let makes a box you can change. const makes a box you promise not to change. Use const by default and let when something needs to move.

    let x = 50;          // a box called x, holding 50
const speed = 3;     // a box you promise not to change
let name = "ball";
let bouncing = false;
x = x + speed;       // read, add, write back
x += speed;          // same thing, shorter
    x = 50               # no keyword; the box appears when you first write to it
speed = 3
name = "ball"
bouncing = False
x = x + speed

    int x = 50;          /* the box is exactly 4 bytes, for whole numbers only */
const float speed = 3.0f;
char name[] = "ball";
int bouncing = 0;    /* old C has no bool; 0 is false */

    int x = 50;
final double speed = 3;
String name = "ball";

x = x + (int) speed;  // Java makes you say when you mix types

    The lesson from the tabs: the idea is identical. Only the spelling and how picky the language is about box sizes changes. Languages like C make you declare the size (which is why they are fast and unforgiving). JavaScript and Python decide for you (which is why they are friendly and a little slower).

    Now make something move

    • Add a let y and a let ySpeed. Make it bounce in both directions.
    • Add speed = speed * 1.1 inside the if. What happens to the box over time? Why does it eventually break?
    • Move let x = 50 inside draw(). Why does the ball stop moving? (Hint: a new box every frame.)

    Scope, in one breath. A box made at the top of the file lives as long as the sketch (global). A box made inside a function is thrown away when the function ends (local). The ball froze above because you kept making a brand new x every frame and throwing it away.

    chapter 2

    Vector vs image data

    There are exactly two ways to store a picture: as a list of instructions, or as a grid of numbers. Everything visual you'll ever make is one, the other, or a conversion between them.

    Vector data is a recipe: "circle at (200,150), radius 30, red. Line from here to there." It is tiny, and it is resolution independent: zoom in forever, it stays crisp, because the computer redraws it from the recipe. SVG files, fonts, pen plotter paths, and every circle() you write in p5 are vector data.

    Raster (image, bitmap, pixel) data is a grid. Each cell is a pixel with four numbers: red, green, blue, alpha, each from 0 to 255. It stores any picture, including photographs that no recipe could describe, but it has a fixed size and zooming in shows the blocks. PNG, JPG, the camera, your screen, and p5's pixels[] array are raster data.

    Inside a raster image: one long list

    The grid is a lie. Memory is one dimensional, so the image is really one long list of numbers, row after row. To find pixel (x, y) you compute an index: (x + y * width) * 4. The * 4 is because each pixel takes four slots: R, G, B, A.

    • In the raster sketch, replace the blue line with pixels[i + 2] = mouseX. Then try (x * y) % 255 for a channel.
    • Make a checkerboard: if ((floor(x/20) + floor(y/20)) % 2 === 0) paint white, else black. (Loops and ifs are chapter 3, feel free to peek.)
    • Try createCanvas(3000, 3000) in the raster sketch and watch it crawl. That is 36 million numbers per frame on one CPU core. Remember this feeling for chapter 7.

    chapter 3

    Loops & conditionals

    Computers are dumb but tireless. Conditionals let a program choose. Loops let it repeat. Together they turn ten lines into ten thousand shapes.

    If asks a yes/no question about a box and does something only when the answer is yes. You already used one: if (x > width). For counts: start a counter, run the block, bump the counter, check if we're done. A loop inside a loop walks a grid, which is why you saw it in the pixels sketch.

    chapter 4

    Functions

    A function is a recipe with a name. You write it once, you call it a hundred times, and you can hand it ingredients.

    You have been calling functions since line one: circle(x, y, d) is a function someone at p5 wrote, and x, y, d are its parameters. Now you write your own. Two reasons to bother: reuse (draw a flower in one place, then draw fifty) and naming (a block called drawFlower is easier to read than twelve lines of trig).

    Some functions also return a value: dist() hands you back a number. Think of it as a box that briefly exists at the place you called it.

    function flower(x, y, size) {   // parameters: x, y, size
  for (let a = 0; a < TWO_PI; a += TWO_PI / 6) {
    circle(x + cos(a) * size, y + sin(a) * size, size);
  }
}

function area(r) {
  return PI * r * r;           // hands a value back
}

flower(200, 150, 30);          // a call, with arguments
let a = area(10);

    chapter 5

    Arrays

    One box holds one thing. An array is a row of numbered boxes under one name. It is how "a ball" becomes "five hundred balls" without writing five hundred variables.

    You met an array already: pixels[] is one, a very long one. Arrays are indexed from 0, so the first item is xs[0], and the last is xs[xs.length - 1]. A for loop from 0 to length visits every one. push() adds to the end, splice(i, 1) removes item i.

    let xs = [10, 40, 90];     // three boxes, one name
xs.push(200);              // now four
xs[0] = 15;                // change the first
for (let i = 0; i < xs.length; i++) {
  circle(xs[i], 100, 20);
}
for (let x of xs) {        // shorter, when you don't need i
  circle(x, 100, 20);
}
    xs = [10, 40, 90]          # a list
xs.append(200)
xs[0] = 15
for x in xs:
    circle(x, 100, 20)

    chapter 6 · the long one

    Random, then Perlin noise

    Randomness is how a program surprises you. Perlin noise is randomness that has learned manners. It is the single most important tool in this whole course, so we take it slowly, with things to play with.

    random() jumps. noise() strolls.

    random() gives you a fresh, unrelated number every call, which looks like static. noise(t) gives you a number that depends on t, and neighbouring ts give neighbouring numbers. Move t a little, the value moves a little. That one property (smoothness) is what makes it look like clouds, terrain, wood grain, wind, handwriting, life.

    Two facts to remember. (1) noise() returns 0 to 1, but in practice hugs the middle (0.3 to 0.7). Use map() to stretch it. (2) It is deterministic: noise(4.2) is the same value every time you ask, until you noiseSeed(). That is what makes it a texture you can look up, not a dice roll.

    How it actually works (the anatomy)

    Ken Perlin invented this in 1983 for the film Tron, because computer graphics looked too clean, and got an Academy Award for it. The idea is tiny:

    1. Put a lattice of points along the number line (in 1D), or a grid (2D), or a cube grid (3D).
    2. Give each lattice point a fixed random thing. The simple version stores a random height (that's called value noise). Perlin's trick is to store a random slope (a gradient) instead, so the bumps don't sit exactly on the grid.
    3. For any position in between, blend the neighbours. Not linearly, because straight lines have visible corners at the lattice, but with a fade curve: 6t⁵ − 15t⁴ + 10t³, which is flat at both ends. That is where the smoothness comes from.

    The lattice spacing in the demo is the same thing as the step you use in code: noise(t) has lattice points at every whole number, so t += 0.01 means 100 frames between lattice points (slow, smooth) and t += 0.5 means two frames per lattice point (jittery). You never change the lattice, you change how fast you walk across it.

    Octaves: noise stacked on noise

    One layer of noise is smooth but boring, like a rolling hill. Real terrain has hills on the hills, and pebbles on those. So you add layers (octaves): each one at double the frequency and a fraction of the amplitude (the falloff, usually 0.5). The sum has big shapes and small detail. This is also called fractal or fBm noise, and in p5 it is noiseDetail(octaves, falloff).

    Noise in 2D and 3D

    noise(x, y) looks up a 2D lattice: a cloud. noise(x, y, t) looks up a 3D one, and if you slowly move t the cloud evolves instead of scrolling. Almost every "organic" animation you have ever seen on a screen is this: 3D noise with time as the third axis.

    • Threshold it: let bright = n > 0.5 ? 255 : 0;. Congratulations, you made islands.
    • Make scale depend on mouseX: let scale = map(mouseX, 0, width, 0.002, 0.1); (inside draw).
    • Colour by band: let band = floor(n * 8); then pick a colour per band. This is the contour view.

    Playable noise systems

    Three things to actually make with it. Each one is "noise controls one parameter of something simple".

    1 · Flow field: noise controls an angle

    Fill the canvas with an invisible grid of arrows. Each arrow's angle is noise(x, y) × some multiple of π. Drop particles in and let the arrows push them. Because noise is smooth, neighbouring arrows agree, and the particles flow like water or wind. This is Coding Challenge 24 and it is still the best afternoon you can spend with p5.

    2 · Wobbly circle: noise controls a radius

    Walk around a circle. At each angle, look up noise at (cos(a), sin(a)), so the lookup is itself a circle and the start joins the end seamlessly. Add the value to the radius. You get a blob. Add time and it breathes.

    3 · Noise walker: noise controls a position

    • In the walker, make the circle size map(noise(tx + 500), 0, 1, 5, 60). Everything can be noise.
    • In the flow field code, change TWO_PI * 2 to TWO_PI * 8, then PI * 0.5. Then replace noise(...) with random() to feel what you'd lose.
    • Colour the flow field by angle: stroke(angle * 40 % 255, 80, 200, 20).

    chapter 7

    CPU vs GPU, and GLSL shaders

    Remember the pixel loop crawling at 3000×3000? Here is why, and here is the fix: a different kind of processor, and a tiny language to talk to it.

    One brilliant worker vs. ten thousand simple ones

    The CPU is a handful of very smart, very fast workers. Your draw() runs on one of them, and it does things in order: this pixel, then the next, then the next. 120,000 pixels per frame is fine. 36 million is not.

    The GPU is thousands of very simple workers. Each one can only do small maths, and none of them can talk to each other, but they all work at the same time. Give every pixel its own worker, and a 4K frame takes about as long as a single pixel would.

    A shader is a function that runs once per pixel

    That is the whole mental model. You write one small function. Its input is "which pixel am I?" (gl_FragCoord). Its output is one colour (gl_FragColor). The GPU runs it for every pixel simultaneously. Because of that, there are rules:

    • You cannot loop over the image. You are already inside the loop. You are one pixel.
    • You cannot read your neighbour's answer. Everyone is answering at the same moment.
    • You can read shared inputs called uniforms: the canvas size, the time, the mouse, an image. Same value for every pixel.
    • The language is GLSL: C-like, strictly typed. float, vec2, vec3, vec4. 1 and 1.0 are different things and it will shout at you. Colours are vec4(r, g, b, a) from 0.0 to 1.0, not 0 to 255.

    There are two shaders in a pipeline: the vertex shader (runs per corner of your geometry, positions it) and the fragment shader (runs per pixel, colours it). For "paint the whole canvas" work, the vertex shader is boilerplate. We give you that one. You write fragments.

    • In Gradient, change to vec4(uv.x, uv.x, uv.x, 1.0). Then vec4(fract(uv.x * 10.0), ...). fract, step, smoothstep, mix, sin: that is 80% of shader art.
    • In Noise, change the loop to 1 octave. Then 8. Compare with chapter 6's octaves demo. It's the same maths, just 130,000 times in parallel.
    • Write 1 instead of 1.0 somewhere. Read the compile error in the console. GLSL is strict because the GPU has no time to guess.

    How p5 wires it up

    The lab hides the JavaScript side. Here it is, so you can do it in your own sketches: make a WEBGL canvas, build the shader from two strings, set uniforms every frame, draw a rectangle that covers the screen.

    chapter 8

    Objects & classes

    Chapter 5 left you juggling parallel arrays: xs, ys, speeds, colours. An object bundles the boxes that belong together. A class is the recipe for making those bundles.

    Step 1: an object is a box of boxes

    Instead of xs[3] and ys[3] and speeds[3], keep one thing: ball.x, ball.y, ball.speed. The flow field code in chapter 6 already did this with { x: ..., y: ... }. Those are object literals: variables with a dot.

    let ball = { x: 50, y: 100, speed: 3 };   // one box holding three labelled boxes
ball.x += ball.speed;                     // the dot reaches inside

    Step 2: a class is a recipe for objects

    When you want many objects with the same shape and the same behaviour, you write a class. Two parts: the constructor sets up the boxes (the data), and methods are functions that belong to the object (the behaviour). this means "the particular object we're talking about right now". new Ball() runs the recipe and hands you one.

    class Ball {
  constructor(x, y) {        // runs on "new Ball(...)"
    this.x = x;              // this = the object being built
    this.y = y;
    this.speed = random(1, 4);
  }
  update() {                 // behaviour
    this.x += this.speed;
  }
  show() {
    circle(this.x, this.y, 20);
  }
}

let b = new Ball(50, 100);
b.update();
b.show();
    import random

class Ball:
    def __init__(self, x, y):       # constructor
        self.x = x                  # self = this
        self.y = y
        self.speed = random.uniform(1, 4)

    def update(self):
        self.x += self.speed

    def show(self):
        circle(self.x, self.y, 20)

b = Ball(50, 100)
b.update()
b.show()
    class Ball {
  float x, y, speed;              // declare the boxes and their types

  Ball(float x_, float y_) {      // constructor
    x = x_; y = y_;
    speed = random(1, 4);
  }
  void update() { x += speed; }
  void show() { circle(x, y, 20); }
}

Ball b = new Ball(50, 100);   // this is Processing, p5's older sibling
b.update();
b.show();
    /* C has structs (data) but no methods; you pass the struct to functions */
typedef struct { float x, y, speed; } Ball;

void ball_update(Ball *b) { b->x += b->speed; }
void ball_show(Ball *b)   { circle(b->x, b->y, 20); }

Ball b = { 50, 100, 2.5 };
ball_update(&b);
ball_show(&b);

    Same idea everywhere: data + behaviour, bundled. The languages differ on how much they make you declare. A struct in C is the "data" half of a class; the "behaviour" half is just functions that take the struct as the first argument, which is exactly what self in Python and this in JavaScript secretly are.

    Step 3: a particle system, using everything

    Variables, loops, functions, arrays, noise, a class. This is the shape of most generative sketches you will ever write: an array of objects, each updated and shown every frame, born on some event, removed when done.

    • Give each particle its own colour in the constructor. Then its own size. Then its own speed multiplier.
    • Add a method applyForce(fx, fy) that nudges velocity. Call it with a wind. (You are now writing The Nature of Code chapter 2.)
    • Make a second class, Emitter, with an array of particles inside it and its own run(). Make three emitters. Objects can hold arrays of objects. It's boxes all the way down.
    • Extra credit: class Spark extends Particle with a different show(). That is inheritance, and it's all you need to know about it today.

    Language agnostic, one last time

    You now know variables, conditionals, loops, functions, arrays and classes. That is the same set of ideas underneath Python, Java, C, C++, Rust, Swift, Go. Pick up any of them and the first week is spelling. The GLSL detour was your proof: you already read a second language in this course without noticing.

    What changes between languages is mostly where the boxes live and who cleans them up (memory), how strictly types are checked, and whether the work is sequential or parallel. You've now touched all three.
