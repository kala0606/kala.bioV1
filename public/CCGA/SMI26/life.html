    SMI26 · cellular automata

    Simple rules, complicated life.

    A cellular automaton is a grid of cells, each either on or off, where every cell looks at its neighbours and follows one tiny rule to decide what it will be next. No boss, no plan, no randomness. And yet: gliders, guns, chaos, computers.

    Three ingredients, every time:

    1. A grid of cells (a line, a sheet, a cube). Each cell has a state: for us, alive or dead, 1 or 0.
    2. A neighbourhood: which cells a cell can see. In 1D, the two beside it. In 2D, the eight around it.
    3. A rule: a lookup table from "what my neighbours look like now" to "what I am next". Every cell applies the rule at the same time, tick, tick, tick. Each tick is a generation.

    That's it. The whole subject is: how much surprise can you squeeze out of ingredient 3.

    The smallest possible version: one row of cells

    Stephen Wolfram's elementary automata are a single line of cells. Each cell has two neighbours, so with itself there are 2×2×2 = 8 possible neighbourhoods. A rule just says, for each of the 8, whether the cell is on or off next. 8 answers, 8 bits, so there are exactly 256 rules, numbered 0 to 255 by reading the bits as a binary number. Draw each generation as a new row underneath and time runs down the page.

    The idea that matters: the rule is 8 bits. The picture is thousands of cells and looks like lace, or static, or a highway. Complexity in the output has nothing to do with complexity in the rule. Hold on to that thought, because it is the thesis of generative art.

    chapter 1

    Conway's four rules

    In 1970 John Conway, a mathematician at Cambridge, went looking for the simplest 2D rule that was neither boring nor explosive. He found it by hand, on a Go board, and Martin Gardner put it in Scientific American. It has been running on every computer since.

    The grid is 2D. Each cell has 8 neighbours (up, down, left, right, four diagonals). Count how many of them are alive. Then:

    If the cell is...and it has...then next generation it is...the story
    alivefewer than 2 live neighboursdeadloneliness
    alive2 or 3alivejust right
    alivemore than 3deadovercrowding
    deadexactly 3alivebirth

    Programmers compress that to B3/S23: Born with 3, Survives with 2 or 3. Everything else dies or stays dead. One line. Hover the grid below and watch the rule being applied.

    • Clear the grid and draw three cells in a row. Step. Step again. You just made a blinker, the simplest oscillator.
    • Draw a 2×2 block. Step. Nothing happens: every live cell has exactly 3 neighbours. A still life.
    • Draw any 5 cells touching, then step 10 times. Can you predict it? (Nobody can, in general. That's the point.)
    // the rule, as code
function nextState(alive, n) {       // n = live neighbours, 0..8
  if (alive && (n === 2 || n === 3)) return 1;   // survive
  if (!alive && n === 3) return 1;               // birth
  return 0;                                      // everything else: dead
}
    def next_state(alive, n):
    if alive and n in (2, 3):
        return 1
    if not alive and n == 3:
        return 1
    return 0
    int next_state(int alive, int n) {
    if (alive && (n == 2 || n == 3)) return 1;
    if (!alive && n == 3) return 1;
    return 0;
}
    // on the GPU, each pixel is a cell and reads its 8 neighbours from the previous frame's texture
float next_state(float alive, float n) {
    if (alive > 0.5 && (n == 2.0 || n == 3.0)) return 1.0;
    if (alive < 0.5 && n == 3.0) return 1.0;
    return 0.0;
}
    chapter 2

    Play.

    Draw on it. Drop in a pattern. Watch the population graph. This is the whole game: there are no players, you only set the first move.

    • Pick empty, draw a messy blob, press play. Count how many generations until it is only still lifes and blinkers. That is "ash", and most random starts end in ash.
    • Pick Gosper glider gun, set edges to dead wall. Then to wrap around. Why does wrapping eventually destroy the gun?
    • Pick random soup and watch the population graph. It always falls, then flattens. Life on a finite grid has a carrying capacity.
    • Pause, draw a glider in front of another glider's path, play. Collisions are how people build logic gates in Life.
    chapter 3

    The zoo

    Fifty years of people watching this thing has produced a taxonomy. Everything in Life is one of four kinds of animal.

    • Still lifes never change. Every live cell has 2 or 3 neighbours, every dead cell doesn't have 3. Block, beehive, loaf.
    • Oscillators repeat with a period. Blinker (2), toad (2), pulsar (3), pentadecathlon (15). Oscillators with every period from 1 upwards have now been found; the last gaps (periods 19 and 41) were filled in 2023.
    • Spaceships move. The glider travels one cell diagonally every 4 generations; the lightweight spaceship goes sideways at half the speed of light (one cell per generation is "c", the speed limit of the grid).
    • Methuselahs are small seeds that take ages to settle. R-pentomino: 5 cells, 1,103 generations. Acorn: 7 cells, 5,206 generations and a glider fleet.

    Then there are the things built out of animals: guns that fire gliders, puffers that leave debris, reflectors, and, since 2000, complete Turing machines made of gliders. Life can run any program, including Life.

    The complete catalogue is the LifeWiki at conwaylife.com. For serious exploring, Golly runs patterns with billions of cells using the HashLife algorithm, which is its own beautiful rabbit hole.

    chapter 4

    Change the rule, change the universe

    B3/S23 is one of 2¹⁸ = 262,144 possible "Life-like" rules on the same grid. Most are dull. A few are famous. Here is the dial.

    Tick a number under B to make dead cells with that many neighbours come alive. Tick one under S to let live cells with that many survive. The presets are the ones people have names for.

    • Start from Life. Add S 4. Then S 5. Watch it go from sparse to solid. Then remove S 2 and see it starve.
    • Find a rule that produces something you would frame. Note its B/S code; that is the whole artwork, 10 characters long.
    • Tick only B 1. Everything explodes in a checkerboard. Rules where B includes 1 are called "explosive" and it's easy to see why.

    Beyond on/off. Cells can have more states (Brian's Brain has "dying"), bigger neighbourhoods (Larger than Life uses radius 5+), continuous values (Lenia, 2019, which produces creatures that look alarmingly alive), or be driven by noise and images. All the same recipe: grid, neighbourhood, rule, tick.

    chapter 5

    Write it yourself

    Life is about forty lines of p5. The only idea you need that the crash course didn't cover is a 2D array: an array of arrays, one row per line of the grid.

    // a 2D array: grid[x][y]
let grid = [];
for (let x = 0; x < cols; x++) {
  grid[x] = [];
  for (let y = 0; y < rows; y++) {
    grid[x][y] = 0;
  }
}
grid[3][5] = 1;
    grid = [[0 for y in range(rows)] for x in range(cols)]
grid[3][5] = 1
    int grid[COLS][ROWS];   /* one contiguous block, rows laid end to end */
grid[3][5] = 1;
/* same thing as the pixels[] trick: index = x + y * COLS */
    • Change the rule lines. Make it HighLife (n === 3 || n === 6 for birth). Make Seeds (birth on 2, nothing survives).
    • Colour cells by how long they've been alive: keep a second 2D array age, bump it when a cell survives, use it in fill().
    • Remove the background() call and set fill(21, 20). Trails. Suddenly it's a texture, not a simulation.
    • Replace floor(random(2)) in seed() with noise(x * 0.1, y * 0.1) > 0.5 ? 1 : 0. Chapter 6 of the crash course meets this one.

    chapter 6

    Why artists care

    Because this is the cleanest demonstration there is of emergence: behaviour at the scale of the whole that is nowhere in the rules of the parts. That is the thing generative artists are chasing, every time.

    • You don't draw the result. You draw the rule. Conway never designed the glider. He designed four sentences and the glider was in there, waiting. Sol LeWitt's wall drawings work the same way: the instruction is the artwork.
    • Determinism without predictability. Life is completely determined (same start, same outcome, forever) and still unpredictable: there is no shortcut to knowing what a pattern does except running it. Wolfram calls this computational irreducibility. Artists call it "let's see what happens".
    • Texture. Rule 30 and Life-like rules are everywhere in generative work as texture generators, mask generators, and growth processes. The noise chapter gives you smooth organic fields; CA gives you crisp, cellular, grown ones. Combining the two (noise seeds, CA grows) is a classic move.
    • Time as material. A CA is a process, not a picture. On a plotter you choose one generation to draw. On a screen you choose a speed. On the blockchain (see the history module), a seed plus a rule is the entire, permanent artwork, and the collector runs it.
    • Sound. Read a row of cells as a step sequencer, or a Life grid as a tone matrix, and you have a generative music machine that is neither random nor repetitive. Brian Eno has been doing versions of this since the 1970s.

    Timeline, roughly

    1940sJohn von Neumann and Stanisław Ulam, at Los Alamos, invent cellular automata to ask whether a machine can build a copy of itself. (Yes: a 29-state CA.)
    1970John Conway's Game of Life, published by Martin Gardner in Scientific American. Gardner's mailbag was the largest for any column he ever wrote.
    1970Bill Gosper's group at MIT finds the glider gun, proving Life can grow without bound. Conway loses $50.
    1983Stephen Wolfram classifies the 256 elementary rules into four classes: dies out, repeats, chaos, and "interesting" (class 4, like rule 110).
    2002Wolfram publishes A New Kind of Science, 1,200 pages arguing that simple programs explain, well, everything. Contested; still provocative.
    2004Matthew Cook's proof that rule 110 is Turing complete is published.
    2019Bert Chan's Lenia: continuous Life, with hundreds of lifelike "species".
    2020John Conway dies of COVID-19, aged 82. He spent decades mildly annoyed that Life was the thing he was most famous for.
