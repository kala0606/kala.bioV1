    SMI26 · servers, explained with a kitchen

    Who cooks the sketch?

    Every web page is a meal. Some are cooked in a kitchen far away. Some are cooked right at your table. Knowing which tells you when your generative sketch needs a server, and when it doesn't.

    One question sorts it all out: whose computer runs the code? If it runs in the visitor's browser, it's the frontend. If it runs on a machine you control, it's the backend.

    When you ask an AI agent for a generative sketch, it usually hands you one .html file. You double-click it and it runs. No server, no install. Then one day the agent says "run python3 -m http.server", or "npm install", or writes a file called server.js, and it isn't clear what changed or why.

    This module explains what changed, with one picture: a restaurant. It also tells you which kind of server your sketch needs, from none at all to a real kitchen, and how to put a bigger Node project on GitHub so anyone can open it.

    Read this after chapters 10 and 11 of From Sand to Sites if you want the engineering version: DNS, TCP, HTTP and how the browser paints. This module is the studio version: what you actually need to do with your sketch.

    chapter 2

    A server is a kitchen that's open

    A server is not a special box. It is any computer running a program that waits for orders and answers them.

    Your laptop becomes a server the moment you type this in a terminal, inside a folder:

    python3 -m http.server 8000

    Now http://localhost:8000 serves that folder. The program sits there, listening at hatch number 8000. When your browser asks for /sketch.js, it finds the file in the folder and hands it over. Close the terminal and the kitchen closes.

    localhost means "this same computer". It's a restaurant inside your own house: only you can walk in. Hosting companies (GitHub Pages, Netlify, Cloudflare) run the same kind of program on kitchens that never close, at addresses the whole world can reach.

    The word gets used for two things, and both are right: the machine (the box in a data centre) and the program on it that listens for requests.

    In your p5 sketch: the p5 web editor at editor.p5js.org is a kitchen someone else runs for you. It stores your files and serves them, which is why loadImage('cat.jpg') works there even though it fails when you double-click a downloaded copy.

    • Make a folder with any .html file in it. Open Terminal, cd into the folder, run the command above, and visit http://localhost:8000. Watch the terminal: every line is one order ticket.
    • Press Ctrl + C in the terminal and reload the page. The kitchen is closed.
    chapter 3

    The bakery: CDN

    You don't bake p5 yourself. A big bakery made it once, and copies sit in depots in hundreds of cities.

    A CDN (content delivery network) keeps copies of popular files on edge servers all over the world. When a student in Bangalore opens your sketch, p5 arrives from a depot nearby, not from the other side of the planet. Almost every single-file sketch an AI agent writes starts with a line like this:

    <script src="https://cdn.jsdelivr.net/npm/p5@1.11.1/lib/p5.min.js"></script>

    That line is the reason a one-file sketch can stay one file. The library isn't in the file. The file only says where to pick it up.

    Two lessons

    • Pin the version. Write p5@1.11.1, not just p5. Otherwise you get whatever bread was baked today. When p5 2.0 changed how loading works, unpinned sketches broke overnight.
    • No internet, no bread. Offline, the canvas stays blank and the console says p5 is not defined. For an exhibition laptop or a gallery install, download p5.min.js, put it next to your HTML, and write <script src="p5.min.js">.

    CDNs aren't only for libraries. Whole websites sit behind them: the CDN keeps copies of your pages near every visitor, and only goes back to your kitchen when something changes. Fonts from Google Fonts arrive the same way.

    • Open any sketch, then the browser's developer tools (⌥⌘I), Network tab, and reload. Find the row for p5.min.js. Which host did it come from, and how many milliseconds did it take?
    chapter 4

    Generative art is cooked at your table

    A p5 sketch works like a hotpot restaurant. The server only hands over a tray: raw ingredients and a recipe card. Your own device does the cooking, frame after frame.

    The composition below was not sent by any server. Nothing came down the wire except the recipe. Your browser cooked it a moment ago from a seed, one rectangle at a time.

    This is exactly how Art Blocks and fx(hash) work (see the Art Blocks chapter of the history module). The recipe, the artist's script, is stored once on the blockchain. Each token is just a hash. When a collector opens the token, their browser cooks the artwork from the hash. The platform serves the tray; the collector's table does the cooking.

    • Delete the randomSeed and noiseSeed lines. Now every run is a different dish. Which version could be sold as a numbered edition?
    chapter 5

    Three levels of "do I need a server?"

    Most confusion comes from mixing these up. A sketch that "needs a server" usually only needs level 2, which never cooks anything. It only hands out files.

    Level 1

    No server

    A recipe card in your pocket. You cook at home.

    Double-click the .html. The address bar starts with file://.

    Works when
    • everything is inside the one HTML file
    • libraries come from a CDN and you're online
    Typical

    A single-file p5 sketch from an AI agent. Agents build for this level on purpose.

    Level 2

    Static server

    A takeaway counter. It hands out packed boxes and never cooks.

    Needed when
    • the sketch loads files: loadImage, loadFont, loadSound, loadJSON, loadShader
    • it uses <script type="module"> and import
    • it uses the webcam or mic
    • you want it at a web address
    On your laptop
    python3 -m http.server 8000
    On the web

    GitHub Pages, Netlify, Cloudflare Pages. This course site lives here.

    Level 3

    Backend

    A real kitchen that cooks each order out of sight.

    Needed when
    • secrets: an API key in the HTML is readable by anyone through View Source
    • shared memory: a class gallery, guestbook, likes, leaderboard
    • multiplayer: the kitchen relays between tables
    • heavy jobs: render 10,000 PNGs, run a big ML model
    • logins and payments
    Looks like

    server.js (Express), app.py (Flask), a Cloudflare Worker, a .env file of keys.

    Why level 2 exists at all

    If level 2 doesn't cook, why can't you just double-click? Because of a safety rule. A page opened from file:// isn't allowed to read other files on your disk. Without that rule, any HTML file you downloaded could quietly read your Documents folder and send it somewhere. Going through http://localhost puts a doorman in between: the page can only ask for files from the one folder you chose to serve.

    The webcam and microphone have a similar rule. The browser only offers them to pages from a trusted address: https:// or localhost.

      chapter 7

      Reading what an AI agent did

      The files and commands an agent produces tell you which level it built for. Here is how to read them.

      you seeit meanslevel
      One .html fileA self-contained sketch with p5 pulled from a CDN. Double-click it.1
      python3 -m http.server
      npx serve      		The sketch loads assets or modules, so the browser needs something that hands out files.2
      npm install
      npm run dev      		A build step (Vite, React). Think of a prep kitchen that chops and bundles, plus a test kitchen that reloads as you edit. npm run build still produces plain static files. A dev server is not a backend. Chapters 8 and 9 cover this.2
      server.js, app.py, a Worker, .envA real kitchen. Code runs on a machine you control, out of the visitor's reach.3

      Asking for the level you want

      You can steer the agent. Say which level you want in the prompt:

      • Level 1: "One self-contained HTML file, p5 from a CDN pinned to 1.11, no external assets, no build step."
      • Level 2: "A folder with index.html, sketch.js and an assets folder. Tell me how to serve it locally."
      • Level 3: "Keep the API key on a small server; the sketch should only talk to my server, never to the AI service directly."
      • Open the last sketch an agent wrote for you. Which level is it? Which line or file decides that?
      chapter 8

      Node: the same cook, in the kitchen

      JavaScript was made to cook at the table, inside the browser. Node takes the same language into the kitchen: it runs JavaScript directly on a computer, with no browser around it.

      Node is what makes npm install, npm run dev and server.js possible. Bigger generative projects use it to pull in libraries (three.js, Tone.js, a noise library, a GUI), split the code into many files, and pack it all up for the web. An AI agent reaches for it as soon as a project outgrows one file.

      thingin the restaurantin your project
      NodeA cook who works in the kitchen instead of at your tableRuns Vite, server.js, or a script that renders 1,000 PNGs
      npmThe wholesale market: millions of ingredients made by other cooksp5, three, tone, simplex-noise, lil-gui
      package.jsonThe shopping list"p5": "^1.11.1"
      package-lock.jsonThe exact receipt: brand and batch of every item, including the ingredients' own ingredientsLets npm ci buy exactly the same things on another computer
      node_modules/The pantry after the delivery arrives. Huge, and anyone can restock it from the listOften 100 to 500 MB. Never upload it.
      npm run devThe test kitchen: cooks a preview and re-plates every time you edithttp://localhost:5173
      npm run buildThe prep kitchen: packs everything into one tray to take awayThe dist/ folder

      A typical shopping list for a sketch built with Vite looks like this:

      {
  "name": "drift",
  "private": true,
  "type": "module",
  "scripts": {
    "dev": "vite",
    "build": "vite build",
    "preview": "vite preview"
  },
  "dependencies": {
    "p5": "^1.11.1",
    "simplex-noise": "^4.0.3"
  },
  "devDependencies": {
    "vite": "^7.0.0"
  }
}

      And the sketch itself imports what it needs, instead of loading it from a CDN. p5 is used in instance mode, where every p5 function hangs off p:

      import p5 from 'p5';
import { createNoise2D } from 'simplex-noise';

const noise2D = createNoise2D();

new p5((p) => {
  p.setup = () => p.createCanvas(600, 600);
  p.draw = () => {
    p.background(244, 239, 230);
    // ... noise2D(x, y) instead of noise(x, y)
  };
});

      Two jobs Node can have

      This is the question that decides everything about shipping. Look at the "scripts" in package.json.

      Job A: the prep kitchen

      Node only runs on your computer, as a tool. Vite bundles your code and the npm packages into plain files in dist/. After the build, no Node is needed: it's a level 2 project, and the tray goes on GitHub Pages.

      Clue: "build": "vite build" (or webpack, parcel, esbuild).

      Job B: the kitchen itself

      Node has to keep running while people visit: Express, Socket.io for multiplayer, saving drawings to a database. That's level 3. GitHub Pages can't run it.

      Clue: "start": "node server.js", or imports like express, socket.io, fs.

      Most generative art projects are Job A. They feel like "a Node project", but what visitors receive is a static tray.

      • Install Node (the LTS version from nodejs.org). In Terminal: npm create vite@latest drift -- --template vanilla, then cd drift, npm install p5, npm run dev.
      • Run du -sh node_modules. That's the pantry. Now run npm run build and du -sh dist. That's the tray.
      chapter 9

      Putting a Node project on GitHub

      The rule: upload the shopping list, not the pantry. GitHub stores your recipe. A build turns it into a tray. A host hands the tray out.

      What goes in the repository

      drift/
      index.htmlcommitthe page Vite starts from
      src/main.jscommityour sketch
      src/Particle.jscommityour classes and helpers
      public/paper.jpgcommitimages, fonts, sounds, copied into the tray as they are
      package.jsoncommitthe shopping list
      package-lock.jsoncommitthe exact receipt, so the build gets the same versions
      vite.config.jscommitbuild settings, including base
      .gitignorecommitthe list of things to leave out
      .github/workflows/deploy.ymlcommitinstructions for GitHub's prep kitchen
      node_modules/ignorethe pantry; restocked with npm ci
      dist/ignorethe tray; GitHub builds a fresh one
      .envignoresecrets never go in a repository

      The pipeline

      1 · your laptopgit pushthe recipe and the shopping list
      2 · GitHub repostores itno pantry, no tray
      3 · GitHub Actionsa borrowed prep kitchennpm ci then npm run build
      4 · GitHub Pagesthe takeaway counterhands out dist/
      5 · the visitorcooks at the tablethe sketch runs in their browser

      Step by step: Vite on GitHub Pages

      1. Leave out the pantry. Make a file called .gitignore: 
        node_modules/
dist/
.env
      2. Make paths relative. A GitHub project site lives at username.github.io/drift/, not at the root of a domain. Tell Vite, in vite.config.js: 
        import { defineConfig } from 'vite';

export default defineConfig({
  base: './',   // load files relative to index.html
});
      3. Push it. Create an empty repository on github.com called drift, then: 
        git init
git add .
git commit -m "first tray"
git branch -M main
git remote add origin https://github.com/USERNAME/drift.git
git push -u origin main
      4. Turn on Pages. On GitHub: Settings → Pages → Build and deployment → Source: GitHub Actions.
      5. Give the prep kitchen its instructions. Add .github/workflows/deploy.yml: 
        name: Deploy to Pages
on:
  push:
    branches: [main]
permissions:
  contents: read
  pages: write
  id-token: write
jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 22
          cache: npm
      - run: npm ci
      - run: npm run build
      - uses: actions/upload-pages-artifact@v3
        with:
          path: dist
  deploy:
    needs: build
    runs-on: ubuntu-latest
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    steps:
      - id: deployment
        uses: actions/deploy-pages@v4
      6. Push again and watch. The Actions tab shows the run. About a minute later the sketch is at https://USERNAME.github.io/drift/. From now on every push rebuilds it.

      The shortcut: let a host do the build. Netlify, Vercel and Cloudflare Pages can import a GitHub repository directly. Set the build command to npm run build and the output folder to dist. Every push rebuilds the site. It's the same pipeline without the workflow file.

      Job B: a Node server

      If Node has to keep running (multiplayer, a shared gallery, an AI call with a secret key), GitHub can only store the code. You need a host that keeps a kitchen open: Render, Railway or Fly.io run node server.js for you, and Cloudflare Workers or Netlify and Vercel functions run small pieces of backend on demand. A common split: the sketch on Pages, one small function for the secret part.

      Put keys in the host's environment variables settings, never in the repository. Anything in a public repository is readable by everyone, forever, even after you delete it.

      Generative art platforms

      • fx(hash) takes a .zip of the built project: index.html at the top of the zip, every path relative. Their command line tool (npx fxhash build) makes the zip. The pantry never goes in. The packed tray does.
      • Art Blocks stores one script on the blockchain, and libraries come only from their approved list. There is no npm at mint time, so the project has to fit level 1.

      When the deploy breaks

      Blank page · 404 for /assets/index-3f9a2c.js

      The tray is looking for files at the root of the domain, but the site lives under /drift/. Set base: './' in vite.config.js.

      npm ci can only install packages when your package.json and package-lock.json are in sync

      The receipt doesn't match the list. Run npm install on your laptop and commit both files together.

      Could not resolve "./Particle.js"

      Works on your Mac, fails on GitHub? The file is called particle.js. macOS ignores capital letters in file names; the Linux machine that builds your site doesn't. Match the name exactly.

      Push rejected · repository is hundreds of MB

      You uploaded the pantry. Add node_modules/ to .gitignore, run git rm -r --cached node_modules, and commit.

      Your API key shows up inside dist/assets/index-….js

      Vite copies every VITE_ variable into the bundle. A build step doesn't hide secrets. A key still needs a backend (level 3).

      chapter 10

      When the canvas goes blank

      Open the console (⌥⌘J in Chrome) and match the message. Most blank canvases are a level problem.

      Uncaught ReferenceError: p5 is not defined

      The bakery delivery never arrived. You're offline, or the CDN link has a typo. Check the URL, or download p5.min.js next to your HTML.

      Access to fetch at 'file:///…/cat.jpg' has been blocked by CORS policy

      You opened the file directly and it tried to read another file from your disk. Run a local server (level 2) and open the localhost address instead.

      Cannot use import statement outside a module

      The code uses import but the script tag has no type="module". Add it, then serve the folder (level 2), because modules won't load from file://.

      NotAllowedError: Permission denied

      The webcam or mic wants a trusted address. Open the sketch through http://localhost or an https:// site, not file://.

      401 Unauthorized · or your API key visible in View Source

      A secret is sitting in the diner's hand. Move that call into a backend (level 3) and let the sketch talk to your kitchen instead. If a key was ever published, cancel it and make a new one.
